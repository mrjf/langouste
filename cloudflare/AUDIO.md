# Reproducible prerecorded pronunciations

Six sample recordings were generated and published on 2026-10-04: three Hungarian
and three Egyptian Arabic, with six successful requests and 114 cumulative credits
reserved/completed. No failed requests or synthesis retries occurred. The reviewed
voices are Attila (Hungarian) and Hany (Egyptian Arabic), using `eleven_v4` at the
model-reported rate of one credit per character. Voice metadata was checked for
native language/accent and educational use. Human listening approval remains
pending; bulk generation remains disabled until that review is received.

The user approved up to US$20 cumulative usage. The generation ledger is capped at
25,000 credits, including samples and any explicitly authorized retries. The full
inventory is 20,401 credits before retries. Published v4 pricing reviewed on
2026-10-04 was $0.022 per 1,000 characters promotional, $0.08 regular; the regular
rate implies $1.63208 for the corpus before taxes. This is a public-price estimate,
not a verified account invoice or remaining-balance report.

The existing key successfully accessed models, voices, shared voices, and synthesis.
`GET /v1/user/subscription` alone returned `missing_permissions` for `user_read`.
No key scope, credentials, subscription, or authentication settings were changed.
The key is loaded only through normal server config and never written to logs.

```sh
bun run audio:course inventory
bun run audio:course preflight
bun run audio:course estimate --profiles /path/to/reviewed-profiles.json
# Only after approving the selected sample voice, model and sample credit ceiling:
bun run audio:course generate --profiles /path/to/reviewed-profiles.json --ids ID1,ID2 --max-credits APPROVED_CEILING --execute-billable
# Listen to samples, then explicitly set sampleApproved=true for each approved voice.
# Only after approving the full credit ceiling:
bun run audio:course generate --profiles /path/to/reviewed-profiles.json --max-credits APPROVED_CUMULATIVE_CEILING --execute-billable
bun run audio:course validate
bun run build:cloudflare
```

The example profile is intentionally not generation-ready. Its multiplier of one
is illustrative, not verified pricing. Use the read-only subscription and model
report to set the actual model rate and approve a cumulative budget. Current
inventory: Hungarian 739 assets / 11,095 characters; Egyptian Arabic 744 assets /
9,306 characters, total 1,483 assets / 20,401 characters. At a verified rate of one
credit/character this would be 20,401 credits before regeneration; monetary cost
and overage depend on the account plan. Short isolated words need listening QA;
model support for Arabic does not establish an Egyptian accent.

`eleven_v4` is pinned explicitly in the example. The single-voice text-to-speech
endpoint accepts an explicit model. Required language support is checked before
synthesis; requests use `hu` or `ar` (not ar-EG), while the local inventory retains
ar-EG. Only stability/similarity settings are permitted for the v4 profile.
Hungarian must not use multilingual_v2. Choose an actual native Hungarian voice
and Egyptian Arabic voice from reviewed metadata; `dialectVerified` means that
metadata has been checked, not that output quality has been proven. Approve a few
samples before setting `sampleApproved`; bulk mode refuses to run without it.
Arabic synthesis uses Arabic-script atoms rather than their transliterations.

Inventory covers target-language atoms, readings, vocabulary, examples, matching
phrases, ordering tokens, supported choices and recall answers. Stable IDs normalize
text to NFC, include language and semantic context, and deduplicate repeated uses.
Generation IDs include voice, explicit model, sorted settings, context and
pronunciation dictionary versions. Pricing changes do not invalidate cached audio.
Private `.inputs.json` files preserve the reviewed inputs; public manifests contain
only asset URLs and hashes. Input reproducibility does not guarantee identical
provider rerenders: keep generated bytes and their SHA-256 hashes.

One process at a time generates sequentially with a one-second pause. It reserves
credits in a durable ledger before requesting audio and atomically publishes each
asset and manifest. Re-running skips already matching assets. Corrupt manifests
or ledgers fail closed. A timeout or provider error can be billable, so there is
no automatic synthesis retry. Inspect the provider history and local files first;
`--retry-uncertain` is an explicit acknowledgement of possible duplicate charges
and counts an additional reservation against the cumulative ceiling. A crashed
process can leave `generation.lock`: verify that no generator is running before
removing that lock. Preserve/reconcile already written MP3 files instead of
blindly regenerating them. Never delete the ledger to evade the budget.

Normal and slow playback reuse the same cached recording; the slow button uses
playbackRate 0.75 with preservesPitch=true. There is no browser/OS/robotic TTS
fallback. Unrecorded pronunciation is labeled honestly. Answer audio is rendered
only with revealed/attempted feedback, never as an advance recall cue. Chrome verified real MP3 decoding and advancing playback time in both languages,
including normal and slow playback of the same asset with pitch preserved. This
verifies playback, not native-speaker pronunciation quality.

Before public audio publication, verify the applicable ElevenLabs license. Free
plan publication is noncommercial with attribution; paid-plan commercial rights
and the time of generation matter. No plan or license entitlement was inferred
from the mere presence of a key.
