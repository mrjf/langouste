## Recommended sequencing

- **Release-blocking first**: 001 → 002 (the IDOR fixes and the tests that prove
  them). In the default sqlite deployment there is no RLS backstop, so these
  membership checks are the *only* access control — do them before publishing.
- **002 depends on 001**: the new tests assert non-members get 403; with 001
  unmerged those assertions fail (which is the proof they're real). Merge 001
  first, or land them together.
- **003 before 009**: both edit `processAgentReply` in
  `src/routes/api/messages.ts`; do 003 (correctness) first, then the streaming
  spike builds on the cleaned-up flow.
- **004, 005, 006, 007, 008 are independent** and can be done in any order /
  parallel. 007 (deps) and 008 (docs/licensing) are the other release-readiness
  items.
- **Spikes (009–011)** produce design docs + PoCs, not shipped features — each
  yields a follow-up build plan. Do them after the P1/P2 fixes.

## Findings considered and rejected (so they aren't re-audited)

- **"Live secrets committed to git history"** (reported by two audit subagents):
  FALSE. `.env` and `.env.supabase` were never tracked — gitignored since the
  first commit; `git log --all -- .env` is empty. Real keys exist only on the
  author's disk. No history rewrite needed. Downgraded to a one-line
  on-disk-hygiene note in plan 008.
- **"SUPABASE_SECRET_KEY missing from .env.example"**: FALSE — present at
  `.env.example:46`.
- **"No issue/PR templates"**: FALSE — `.github/ISSUE_TEMPLATE/{bug_report,
  feature_request,config}.yml` and `.github/PULL_REQUEST_TEMPLATE.md` all exist.
- **"SECURITY.md has no reporting contact"**: FALSE — SECURITY.md documents
  GitHub private vulnerability reporting + owner email. Dropped.
- **"Exercises is a dead 1,874-line file / gate it"**: FALSE — it's wired to the
  client (`ExercisePanel.svelte`, an `exercises` nav view, a live route). The
  real question is completeness/coverage — folded into spike 011, not a
  gate-the-dead-code plan.
- **"Schema drift between sqlite and supabase (ARCH-5)"**: no *current* drift —
  table sets match exactly (sqlite's extra `users` table is correct for local
  auth). The *absence of an automated sync check* is a legitimate DX prevention
  item (noted in plans 006/010 maintenance notes) but there is no live bug to
  fix, so no standalone plan.
- **SM-2 timezone math, OpenClaw/HTTP frame validation, vocabulary substring
  self-correction match, agent-connection cache without config hash**
  (CORRECT-05/07/08/10/12/14): real but LOW impact and/or already mitigated
  (e.g. the connection cache is evicted on config change via `disconnectAgent`).
  Not worth dedicated plans now; revisit if they surface in practice.
- **God-file decomposition (ProfilePanel/WorkbenchPanel/generator >1600 LOC)**:
  real maintainability debt, but risky refactors with no functional payoff for
  release. Deferred — not release-blocking.
- **Abandoned NLP deps (nspell/phonemize/@piper-plus/g2p/transliteration)**:
  staleness, not a CVE; `phonemize`/`@piper-plus/g2p` appear only in a `.d.ts`
  stub with no runtime import (possible dead deps). Worth a cleanup pass later;
  kept out of the CVE-focused plan 007 deliberately.

## What was not deeply audited

LLM-eval suite quality; Supabase RLS policy correctness under multi-user load;
CSRF/rate-limiting (no rate limiting exists — worth noting for any hosted
deployment, but the default target is local single-user). None of these block
the source-only local-sqlite release the project is shipping first.
